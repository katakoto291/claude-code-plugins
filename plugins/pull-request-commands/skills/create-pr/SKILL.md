# PR作成スキル

## 概要

このスキルは、現在のブランチの変更内容を分析し、適切なPRタイトルと説明文を生成してからGitHub PRを作成します。ユーザーが草案を確認してから実行するので、意図しないPRが作られることはありません。

## 手順

### 1. ベースブランチの決定

ユーザーがスキル呼び出し時に引数でブランチ名を指定した場合（例: `develop` や `staging`）はそれをベースブランチとして使用する。指定がない場合は `main` → `master` の順でリポジトリに存在するブランチを確認して決定する。

### 2. 現在のブランチ情報を収集

以下を並行して確認する（`<base>` は上で決定したベースブランチ）：

```bash
git status
git branch --show-current
git log <base>...HEAD --oneline
git diff <base>...HEAD --stat
git diff <base>...HEAD
```

- リモートへのプッシュ状態も確認する（`git status` で "ahead of" の有無）

PRテンプレートを探す（以下の順で確認）：

```bash
cat .github/pull_request_template.md 2>/dev/null || \
cat .github/PULL_REQUEST_TEMPLATE.md 2>/dev/null || \
cat docs/pull_request_template.md 2>/dev/null || \
echo "NO_TEMPLATE"
```

### 2. PRタイトルと説明文を生成

収集した情報から草案を作成する。

**タイトルのガイドライン：**

- 変更の本質を簡潔に表現（70文字以内）
- リポジトリでConventional Commitsが使われていれば合わせる（例: `feat:`, `fix:`, `chore:`）
- コミットメッセージをそのまま使うのではなく、変更全体を俯瞰したタイトルにする

**PRテンプレートがある場合：**
テンプレートの構造をそのまま使い、各セクションを変更内容に合わせて埋める。テンプレートのチェックボックスや見出しは変更しない。

**PRテンプレートがない場合のデフォルトテンプレート：**

```
## 変更内容
- [変更点を箇条書きで]

## テスト手順
- [ ] [確認手順1]
- [ ] [確認手順2]

## 関連Issue
Closes #[issue番号]
```

**テスト手順の書き方：**
変更内容から、レビュアーが動作確認するために必要な手順を推測して記載する。たとえば：

- UIの変更なら「〇〇ページを開き、□□ボタンをクリックして動作を確認」
- APIの変更なら「〇〇エンドポイントにリクエストを送り、レスポンスを確認」
- 設定変更なら「〇〇コマンドを実行して正常に動作することを確認」

具体的な手順が判断できない場合は「動作確認が必要な箇所を確認してください」などの一般的な記載でよい。

関連Issueはコミットメッセージやブランチ名（例: `feature/issue-123-xxx`）から推測できる場合のみ記載する。見当たらない場合はこのセクションを省略する。

### 3. 草案をユーザーに提示して確認

生成した草案を以下の形式で表示する：

```
**タイトル:**
[生成したタイトル]

**説明文:**
[生成した説明文]

このPRをDraftとして作成しますか？修正があれば教えてください。（Draftなしで作成したい場合はその旨を伝えてください）
```

ユーザーが修正を求めた場合は内容を更新してから次のステップへ進む。

### 4. gh pr create を実行

ユーザーが確認したら：

1. リモートにプッシュされていない場合は先に実行：

   ```bash
   git push -u origin <current-branch>
   ```

2. PRを作成（デフォルトはDraftで作成）：

   ```bash
   gh pr create --draft --base <base> --title "<タイトル>" --body "$(cat <<'EOF'
   <説明文>
   EOF
   )"
   ```

3. 作成されたPRのURLをユーザーに表示する。

## トラブルシューティング

- **ベースブランチが不明な場合**: 引数がなく `main` も `master` も存在しない場合はユーザーに確認する
- **`gh` コマンドが未インストール**: `brew install gh && gh auth login` を案内する
- **認証されていない**: `gh auth login` を実行するよう案内する
- **変更がない場合**: コミットされていない変更があれば先にコミットするよう案内する
